# Folder Open Tabs

Zen Browserのフォルダー内にある、アンロードされていないタブを枠線で区別する個人用CSS・Sine JS Modです。フォルダーを閉じても対象のタブを表示したままにし、表示中タブの選択背景、ページ切替、タブ終了を滑らかにします。

## 表示

| タブの状態 | フォルダーを開いているとき | フォルダーを閉じたとき |
| --- | --- | --- |
| 現在表示しているタブ | Zen標準の選択中背景 | 表示を維持 |
| アンロードされていない非選択タブ | 輪郭に細い枠線 | 枠線付きで表示 |
| アンロード済みのタブ | 枠線なし | 非表示 |

枠線にはタブの文字色を基準にした半透明色を使います。タブの大きさは変えず、選択中の背景色も上書きしません。サイドバーのタブ背景、ロード済みタブの枠線、ホバー背景を13px、タブの閉じる・アンロードボタンとフォルダーのアンロードボタンを8pxの角丸へ調整します。表示中のタブを切り替えると、選択背景が360msで次のタブへ移動し、到達点をわずかに越えてから収束します。同時にページ本体を98.5%の縮尺から160msで自然な大きさへ戻し、奥から手前へ来る奥行きを加えます。不透明度は変更せず、切替待ちも増えません。フォルダー外の通常タブを閉じると、タブ本体は即座に隠れ、60個の小片だけが最大約515msで粉状に溶けます。右側の閉じるボタン付近から最大220msずらして順に左側へ崩れ、各粒子は約225〜295msで素早く消滅します。粒子は左上へ1.5〜4pxだけ流れます。他のタブは閉じた位置を90ms維持した後、160msかけて滑らかに上詰めします。閉じたフォルダー内のロード済みタブで右端の閉じるボタンを押すと、枠線・名前・アイコンを含むタブ外観が560msで右へわずかにはがれ、表示を保ったまま上へ移動し、最後に細く畳まれてフォルダーアイコンへ格納されます。この操作はZen内部でタブ削除ではなくアンロードとして処理されます。アンロード開始前に終了レイヤーを作るため、タブが`pending`化した後もアニメーションを維持します。フォルダー見出し下の短い発光線が到着を示します。アンロード処理自体は遅延させません。フォルダー開閉などで選択タブ自体が移動する間も、選択背景が毎フレーム追従します。OSで視覚効果を減らす設定が有効な場合、これらのアニメーションは無効になります。入れ子になったフォルダーでは、対象のタブまでのフォルダー階層も残します。

フォルダー開閉は、Zen標準の180msアニメーションを280msの`ease-in-out`へ延長します。タブの展開・縮小、アンロード済みタブの非表示、フォルダーアイコンを同じ速度へ揃えます。閉鎖開始時はアンロード済みタブの展開高を1フレーム保持してから縮小し、フォルダー内タブを表示中でも閉鎖アニメーションを省略しません。ロード済みタブを含むフォルダーでは閉鎖中から展開完了まで開閉スペーサーを無効化し、ロード済みタブの表示領域を全フレーム維持します。アンロード済みタブだけ縮小・格納します。全タブがアンロード済みの場合は、Zen標準の行・余白アニメーションを280msへ調整し、余白の終点を補正します。独自のfollower補正はこの経路では使いません。これにより、後続タブが途中で終点へ着かず、開閉とも280ms全体を使って移動します。フォルダー展開中だけタブ領域のスクロールアンカーを停止し、フォルダー後方の通常タブと新しいタブボタンの位置をスペーサーへ毎フレーム同期します。短いフォルダーを開く間も、選択中の通常タブを展開完了まで固定せず連続して移動します。フォルダー内の最後の実タブを閉じてZenが通常タブへ自動移動した場合も、閉鎖中のDOM更新後に選択状態を再照合します。通常タブの描画位置が確定するまで旧ハイライト位置を保持し、確定後は通常の360msアニメーションで通常タブへ移動します。選択外観は非ホバーかつ選択状態確定後に保存し、クリック直後のホバー背景が選択ハイライトへ固定される競合を防ぎます。


## 表示の判定

タブの判定には、タブ要素の `pending` / `discarded` 属性を使います。クリックしたタブの履歴を記録する仕組みではありません。クリックして開いたタブでも、その後アンロードされると、枠線とフォルダーを閉じた後の表示が消えます。セッション復元などで読み込まれたタブも対象です。

## 導入

選択背景の移動アニメーションにはSineとローカルJavaScript Modの許可が必要です。Sineの設定で外部ModのJavaScriptを許可し、このリポジトリをローカルModとしてインストールしてからZenを再起動します。`theme.json`が`chrome.css`と`folder-open-tabs.uc.mjs`を読み込みます。

CSS機能だけを使う場合は、次の手順でも導入できます。この方法では選択背景の移動アニメーションは動作しません。

1. Zenで `about:support` を開き、「プロファイルフォルダー」を開きます。
2. 既存の `chrome/userChrome.css` がある場合は、先にバックアップします。`chrome` フォルダーがなければ作成します。
3. このプロジェクトの `chrome.css` を、プロファイル内の `chrome/folder-open-tabs.css` としてコピーします。
4. このプロジェクトの [`chrome/userChrome.css`](chrome/userChrome.css) を、プロファイル内の `chrome/userChrome.css` としてコピーします。既存の `userChrome.css` がある場合は上書きせず、ファイル末尾に次の行を追加します。

   ```css
   @import url("folder-open-tabs.css");
   ```

5. `about:config` で `toolkit.legacyUserProfileCustomizations.stylesheets` を `true` にします。
6. Zenを再起動します。

`chrome/userChrome.css` は、Zenのプロファイルから読み込む入口ファイルです。プロジェクト内にもCSS単体利用向けのコピー用テンプレートを置いています。既存の自動生成ファイル `zen-themes.css` は編集しないでください。

取り外すときは、追加した `@import` の行を削除してZenを再起動します。他の個人用CSSがある場合は、そのファイルやスタイルシート設定を変更する必要はありません。

## 今回の変更

### 0.4.82: 性能・ライフサイクルの改善

Windows版Zen Browser 1.22.3b（更新チャネル `release`、Firefox 156.0.1、Build ID `20260922050124`）の隔離プロファイルで検証しました。

- 展開アイコンと行要素を保持し、DOM変更時だけ参照を更新します。座標の読み取りとstyleの書き込みを分離し、変化のないtransform設定を省略します。
- レイアウト通知をフレーム単位にまとめます。Mod自身のtransform変更と、位置に関係しない装飾イベントによる再追従を抑えます。
- 選択外観は変更時に再取得し、変化したstyle値だけ反映します。外部の選択背景変更への追従もテストしています。
- 通常タブ終了の60粒子は維持し、同時演出を最大3件・180粒子に制限します。粒子ごとのblurアニメーションを除去し、アンロード枠線の移動はtransformへ変更します。
- タイマー・rAFを破棄時に取り消し、閉鎖待機に期限を設けます。展開終了処理の参照数管理と古い処理の検出を修正します。
- Zen標準の開閉アニメーションだけを280msへ変更します。独自の360ms行表示と、無関係な900msアニメーションが変更されないことを確認しています。
- 展開時の旧高さの取得順と、最後のタブ終了後の旧ハイライト位置保持を修正し、後方タブと自動選択先への連続移動を維持します。
- CSSの重複、到達不能な追従分岐、メタデータのバージョン不一致を解消します。テストは実行環境を記録し、正常終了後に今回作成した隔離プロファイルを削除します。

同一ハーネスによる比較では、100タブ展開の `getComputedStyle` 呼び出しが20,266回から826回、アイコン探索が2,900回から200回へ減少しました。CPU・GPU・FPSの測定ではありません。比較データは [`tests/performance-before.json`](tests/performance-before.json) と [`tests/performance-after.json`](tests/performance-after.json) に保存しています。計測は `node tests/performance-audit.mjs` で実行できます。

- フォルダー開閉のタブ移動とアイコンが280msの`ease-in-out`で動き、選択背景が途中フレームから追従すること。

- 通常タブを表示した状態でフォルダーを開いても、ロード済みタブが全フレーム表示され、一度格納される動きが発生しないこと。

- フォルダー内タブの一括削除後、通常タブの描画確定が遅れても旧座標を失わず、ハイライトが360msで通常タブへ移動すること。

## 制約

このModのCSSとJavaScriptは表示だけを変更し、Zen内部のタブ管理は変更しません。JavaScriptは選択背景用の要素を1つ追加し、タブ選択時にWeb Animations APIで位置と大きさを補間します。通常タブを閉じるときは、タブ本体を非表示にして粒子だけを一時要素へ生成し、アニメーション完了後に削除します。閉じたフォルダー内のロード済みタブで閉じる操作をするときは、`explicitUnloadTabs()`呼び出し前の背景・枠線・名前・アイコンを一時要素へ再構成し、フォルダーアイコンへ移動してから削除します。ウィンドウの画像キャプチャは使用しません。フォルダーを閉じた後に追加表示する非選択タブでは、内部の `tab.visible` が `false`、`aria-hidden` が `true` のままになることを実機で確認しています。

マウスによるタブの選択はテスト済みです。一方、内部の表示判定を使うキーボード移動やドラッグ操作、スクリーンリーダーとは整合しません。CSSからこれらの属性や内部一覧を修正することはできません。内部動作まで一致させるには、通常のCSS Modとは別に、Zen本体側の対応を検討する必要があります。

Split View、Live Folders、別OS、他のModとの併用は未検証です。フォルダーを閉じるときは、アンロード済みタブだけを280msの`ease-in-out`で縮小・フェードし、ロード済みタブは表示を維持します。再び開くときもロード済みタブの位置を維持し、アンロード済みタブだけを展開します。Zenの将来の更新で内部構造が変わった場合は、再確認が必要です。
